## 1. 准备（一次性）

### 1.1 注册 Partner Center 开发者账号

1. 打开 <https://partner.microsoft.com/dashboard>，用**长期使用的邮箱**注册
   （这个邮箱以后是审核沟通入口，别用小号）。
2. 选「个人」或「公司」开发者。个人账号注册费低、验证简单，本应用是免费工具，
   个人账号足够。
3. 完成身份验证（可能需要身份证件/企业资质），**审核 1~3 个工作日**，
   这一步是整个流程里最长的等待，越早开始越好。

### 1.2 预留应用名称

1. Partner Center → 「创建新应用」→ 名称填 **`桌面歌词`**。
2. 名称被占用时试变体：`桌面歌词 Desktop-sing`、`桌面歌词 Lite` 等。
   预留后名称会被保留一段时间，期间别人占不走。
3. **这个名称就是商店里显示的商品名**，请与清单里的 `DisplayName`（`桌面歌词`，
   在 `store/build_store.py` 的 `DISPLAY_NAME`）保持一致 —— 元数据与实际产品不符
   是 10.1.1 的典型判罚点。

### 1.3 抄回包标识，写入 `store/identity.local.json`

1. 应用 → 「产品管理」→「产品标识」，复制三行：
   - **Package/Identity/Name**，形如 `12345Desktop-sing`
   - **Package/Identity/Publisher**，形如 `CN=1A2B3C4D-5E6F-...`
   - **Package/Properties/PublisherDisplayName**（个人账号通常就是**真实姓名**，
     千万别写成产品名 —— 它也被逐字符校验，填错报
     *应用清单中的 PublisherDisplayName 元素…与发布者显示名称不匹配*）
   - 同一页还能看到 **Package Family Name**，形如 `12345Desktop-sing_8ahsnwh40hshg`，
     也一并抄下来（用途见第 3 步）。
2. ⚠️ **必须原样复制，不能手敲**。Publisher 是微软签发证书的主题串，
   **逐字符匹配**，错一个字符包就装不上（报证书与清单不匹配）。
3. 写入本机标识文件（**勿提交、勿外传**，`.gitignore` 已拦）。
   顺手把**应用名**与 §1.4 的**站点根地址**也写进去 —— 出包时会打印出来、`--listing`
   会自动把产品名称与两个隐私政策地址填进提审文案，省得到时手拼：

   ```json
   {
     "name": "12345Desktop-sing",
     "publisher": "CN=1A2B3C4D-5E6F-...",
     "publisher_display_name": "张三",
     "display_name": "桌面歌词|Desktop-sing",
     "site_url": "https://xxx.netlify.app",
     "package_family_name": "12345Desktop-sing_8ahsnwh40hshg"
   }
   ```

   **`package_family_name` 是防抄错的保险**：PFN 的后半段就是从 Publisher 字符串算出来的
   哈希（`sha256(Publisher 的 UTF-16LE 编码)` 取前 64 位，按每字符 5 bit 编成 13 位小写
   自定义 base32，字母表 `0-9a-hj-km-np-tv-z`，末位补 0）。填上它，自检的 `P5.20c3`
   就会**独立反推一遍**：算出来对不上一律 FAIL，等于替你把「手敲错一个字符」这种
   最容易漏、代价最大（白跑一次提审）的错误在本地拦下。现有配置已实测通过：
   反推结果 `8ahsnwh40hshg` = Partner Center 页面值。

   **`display_name` 必须是 Partner Center 预留过的名字之一，逐字符相等**（在
   「应用名称」/「管理应用名称」页面抄）。包内 `<DisplayName>` 对不上预留名，上传即刻被拒：
   *The name found in the package is not one of your reserved app names*。
   ⚠️ **半角 `|`(U+007C) 与全角 `｜`(U+FF5C) 是两个字符**——本机测试那两次
   「看着一样却传不上去」基本都栽在这种隐形字符上。默认值已是 `桌面歌词|Desktop-sing`，
   只有换名时才需要覆盖。

   `site_url` 末尾带不带 `/` 都行（会归一化掉）。五项都可以临时用命令行覆盖：
   `--name` / `--publisher` / `--publisher-display-name` / `--display-name` / `--site-url`。

4. 验证是否生效 —— 重新出包，控制台**不应**再出现占位警告：

   ```bash
   .buildenv\Scripts\python.exe store\build_store.py
   ```

   ```
   标识   : 12345Desktop-sing          ← 应为你自己的值
   发布者 : CN=1A2B3C4D-...            ← 应为你自己的值
   发布者名: 张三                       ← PublisherDisplayName，别写成产品名
   应用名 : 桌面歌词|Desktop-sing       ← 应等于预留名
   隐私页 : https://xxx.netlify.app/privacy.html
   ```

   若打印 `Desktop-sing-PLACEHOLDER` / `CN=PLACEHOLDER-FILL-ME`、`隐私页 : （未配 site_url…）`，
   或末尾出现「⚠️ 当前是占位标识：上传前必须填真实 Identity」，说明文件没读到。

   再跑一次自检，`P5.20a` / `P5.20a2` / `P5.20b` 的三条 WARN 应该消失，
   取而代之的是三条 PASS；**没重出包之前 `P5.20c` 会 FAIL**（本地标识填了、`out/` 里还是旧包），
   **逐字段抄错由 `P5.20c2` FAIL**，**Publisher 哈希反推对不上由 `P5.20c3` FAIL**，
   **改了应用名没重出包则由 `P5.20d` FAIL**。
   **`P5.20c4` 另外盯着 `store/out/` 根目录里只能有一个 `.msix`** ——
   多出来的（历史版本、自签测试包）都是上传时选错文件的隐患，挪到 `store/out/dev/` 即可。

   > 发版改标识时的**唯一正确顺序**：改 `identity.local.json` → 重跑 `build_store.py`
   > → 跑 `audit_round3.py`（要求 FAIL 0 / WARN 0）→ 再上传。跳过中间那步就是
   > 「本地是对的、包里还是旧的」，`P5.20c` 专治这个。

   > 优先级：命令行 `--name/--publisher/--publisher-display-name/--display-name/--site-url` → `identity.local.json`
   > → 内置默认值（占位标识 / 预留名常量）。临时试包可以用命令行传参，
   > 但**正式提审建议落文件**，免得手滑漏参数发出占位包。

## 3. 每次提审：本地验收

### 3.1 离线自检（必做，1 分钟）

```bash
.buildenv\Scripts\python.exe store\audit_round3.py
```

它强制 `STORE_MODE=True`、真实实例化浮层与设置面板并走一遍 `refresh()`，
同时核对：清单与资产完整性、随包文档（中英 5 份）、隐私政策与代码行为一致性、
对外文档口径（不含逆向细节）、商店截图素材。**全过再上传，心里有底。**

### 3.2 WACK 认证（建议，需管理员）

```bash
.buildenv\Scripts\python.exe store\build_store.py --wack
```

`appcert.exe` 就是商店审核用的那套测试集，本地过了基本不会栽在技术认证上。
**非管理员环境会 `Permission denied`，属预期，不是代码问题** —— 换管理员终端再跑。

### 3.3 自签安装 + 商店模式行为核对（强烈建议）

未签名的 MSIX 本机装不上，需临时自签（完整命令见 `README-STORE.md` §3）：

```powershell
# Subject 必须与清单 Publisher 逐字符一致
$cert = New-SelfSignedCertificate -Type Custom -Subject "CN=你的Publisher" `
  -KeyUsage DigitalSignature -FriendlyName "Desktop-sing 本地测试" `
  -CertStoreLocation "Cert:\CurrentUser\My" -TextExtension @(
    "2.5.29.37={text}1.3.6.1.5.5.7.3.3", "2.5.29.19={text}")
signtool sign /fd SHA256 /sha1 <证书指纹> store\out\Desktop-sing-<版本>-x64.msix
Export-Certificate -Cert $cert -FilePath test.cer
Import-Certificate -FilePath test.cer -CertStoreLocation "Cert:\LocalMachine\TrustedPeople"
Add-AppxPackage -Path store\out\Desktop-sing-<版本>-x64.msix
```

## 5. 认证与发布

1. 提交后状态依次：`预处理中 → 认证中 → 发布中 → 已发布`。
   认证通常几小时到 1~2 天，**首次提交往往更久**。
2. **认证失败**：在提交报告里能看到具体条款号与描述。对照 `README-STORE.md` §9
   「常见拒审原因对照」定位 → 改文案/改代码 → **版本号递增** → 重出包 → 重新提交
   （见 §2 全流程）。
3. **认证通过后**商店自动向用户推送更新，不需要用户操作，也不需要我们做任何事。
4. 想暂停发布或回滚：Partner Center 可以把某次提交「停止发布」，
   但**已安装的用户不会被远程卸载**，只能发新版本修正。

## 7. 卡点速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 出包打印 `PLACEHOLDER` / 上传后被拒 | 没填 `store/identity.local.json` | §1.3 |
| 上传被拒：*name found in the package is not one of your reserved app names* | 清单 `<DisplayName>` 与预留名不一致（多半是全角 `｜` / 半角 `\|` 混用，或改了名没重出包） | 核对 Partner Center 应用名页面逐字符抄，改写 `identity.local.json` 的 `display_name` 后重出包；`P5.20d` 会守住这条线 |
| MSIX 装不上，报证书/发布者不匹配 | 自签证书 Subject 与清单 `Publisher` 不一致 | 逐字符对齐，勿手敲 |
| 重打包报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（exit 1） | 覆盖旧 `.msix` 被安全策略拦 | 先把旧文件移回收站/删掉再重跑 |
| `makeappx` 报找不到资产 | 清单引用了包里没有的图标 | 跑 `store/make_store_assets.py` 重新生成资产，再 `build_store.py` 出包（出包时会自检清单引用的每个资产是否都在） |
| WACK `Permission denied` | 不是管理员 | 管理员终端再跑 |
| 审核说「描述不准确」 | 描述与实际功能不符 | 逐条核对 listing §3 的限制段；界面语言、SMTC 前提、系统版本三项最容易被挑 |
| 审核说「测不出功能」 | 审核员不知道要接播放器 | listing §7 认证说明必须写清 SMTC 与快捷键默认关闭 |
| 审核说「缺隐私政策」 | URL 没填或打不开 | §1.4，注意 URL 必须长期有效 |
| 提交后提示受限功能需批准 | `runFullTrust` 正常预警 | 填两句话说明即可，不阻碍提交 |
| 版本号被拒 | 与上次相同 | 版本号必须递增（四段） |

# 桌面歌词（BetterLyrics 风格）

一个常驻桌面的歌词悬浮条：自动读取 **QQ音乐 / 网易云音乐 / 酷狗音乐**（或其它接入 Windows 系统媒体栏
的播放器）正在播放的歌曲，显示专辑封面 + 卡拉OK式逐句歌词，配色随封面自动变化。

![效果](#) 当前句流光填色 · 封面主色提取 · 玻璃拟态胶囊 · 均衡器动画 · 底部进度条

## 功能

- **自动跟随播放**：通过 Windows 系统媒体控制（SMTC）读取当前歌曲（标题 / 歌手 / 专辑 / 封面 / 播放进度），换歌自动切换；同时开着 QQ音乐和网易云时，跟随正在播放的那个；**播放进度做连续性校正**——本地按真实时间外推，播放器小抖动（如网易云 SMTC 0~0.5s 跳变）、上报滞后甚至**上报冻结**（音乐在放但播放器位置不上报）都不会拽停歌词，只有快进/拖动/大幅回退才重新对齐
- **歌词自动匹配（多源择优）**：播网易云的歌优先走网易云接口（weapi 加密搜索 + 歌词接口，独家版权歌匹配更好），否则按 QQ音乐 → 网易云 → **酷狗** → **LRCLIB** 依次取词；每个来源都先算**质量分**（有逐字 +30 / 有翻译 +12 / 行数 / 末行是否贴合歌曲全长）再择优，**拿到「逐字 + 翻译」的满配结果就提前收工**，不再无谓跑完剩下的源。结果本地缓存
- **逐字歌词四来源**：QQ `trans`、网易云 YRC / `tlyric`、**酷狗 KRC**（自带逐字时间轴与 `[language:]` 译文）、LRCLIB（偶有带逐字增强标签的版本）——任意一个能拿到逐字就按逐字渲染
- **歌词清洗（借鉴 Lyricify 的 Lyrics Optimization）**：自动剔除空行 / 纯符号行、**版权声明与制作名单**（`作词：`／`小提琴：`／`母带工程师：`／`特别支持：` 等 60+ 种角色，"角色 + 冒号"才算，不会误伤「鼓起勇气」这类正常歌词）、同一时间戳的重复行只留第一条，并按时间重排（`words` 行号同步重建）
- **繁简转换（可选）**：内置 900+ 组高频繁简对照；把完整对照表放到 `%APPDATA%\Desktop-sing\t2s.tsv`（每行「繁体<TAB>简体」）即可覆盖内置表。表中未收录的字符原样保留，**绝不猜**
- **BetterLyrics 式视觉**：
  - 当前句卡拉OK式流光填色（渐变色取自专辑封面主色）
  - 封面主色同时驱动胶囊底色、边框、均衡器与进度条
  - 行切换滑入淡入动画、胶囊宽度平滑过渡、播放中标题旁有均衡器律动
  - **氛围光晕**：卡片外圈铺一层封面主色径向光晕，随音乐轻微呼吸
- **翻译 / 音译歌词**：QQ音乐 `trans`、网易云 `tlyric` 自动解析并按时间轴匹配到对应行，以小一号、副主色着色的方式显示在当前句下方（可在面板/菜单开关）
- **9 种逐字动画**：流光滑入 / 字字上浮 / 缩放入场 / 纯淡入 / 弹跳落字 / 波浪起伏 / **扇形展开** / 打字机 / 无动画——逐字（不是逐行）驱动，唱到哪个字就动哪个字
- **字体库（免费商用字体一键下载 + 国内镜像回退）**：内置钉钉进步体、MiSans、阿里巴巴普惠体 3.0、思源黑体、霞鹜文楷、得意黑 6 款**免费商用**字体，面板里点一下即下载安装并立即生效；每款字体按「主 CDN → ghfast.top / ghproxy.net 等国内镜像」顺序自动回退，避免单一下载源抽风导致失败
- **桌面集成**：置顶无边框悬浮条、拖拽移动（位置记忆）、鼠标点击穿透、**位置锁定**（防误拖）、托盘图标控制、**暂停自动淡出**
- **摆放位置预设（7 个锚点）**：底部居中（贴任务栏上方，默认）/ 顶部居中 / 屏幕正中 / 四角，右键或托盘菜单「摆放位置」里一键切换。存的是**相对屏幕安全区的锚点**而不是绝对坐标，所以换分辨率、改任务栏高度、插拔外接屏之后仍然贴边；手动拖过会自动落到「自由摆放」并记住坐标（借鉴 FluentFlyout 的浮层位置定制）
- **全局快捷键**：`Ctrl+Alt+P` 播放/暂停、`Ctrl+Alt+,` / `Ctrl+Alt+.` 上/下一首、`Ctrl+Alt+[` / `]` 歌词偏移、`L` 显示隐藏、`S` 设置、`T` 样式、`D` 显示模式、`G` 锁定位置、`B` 氛围屏保——**默认关闭**（避免和别的软件抢键），需要时在面板/托盘里打开；被占用的组合会自动跳过并提示
- **氛围屏保（黑底防烧屏）**：全屏待机画面——纯黑打底 + 封面主色大光晕 + 低亮度大时钟 + 当前歌词，所有元素按**互不相同的慢周期**漂移，长时间挂着也不会烧屏；可设空闲 N 分钟自动进入（默认 10 分钟），系统锁屏期间不会重复启动，按任意键 / 点一下鼠标退出
- **开机自启 + 进程保活**：自启写入注册表 Run 项；保活由一个轻量守护进程守着——先挂到当前 PID 上，进程被强杀 / 崩溃后自动拉起，退避重启避免崩溃风暴；应用内点「退出」是正常退出，守护进程随之下班，不会诈尸
- **设置面板**：卡片式现代深色 UI——自绘开关、分段选择器、主色实心圆播放键、圆角胶囊菜单，配色实时跟随专辑封面主色；按「歌词同步 / 外观 / 字体库 / 悬浮窗 / 氛围屏保 / 系统」分组，内容可滚动
- **播放控制**：上一首 / 播放·暂停 / 下一首（系统媒体键），悬停一键控制条 + 双击播放/暂停；歌词偏移校准（±5s，正值为提前）；「重新获取歌词」可手动纠正匹配错误的歌词

## 安装

需要 Windows 10/11 与 Python 3.8+：

```bat
pip install -r requirements.txt
```

## 运行

**方式一（源码）**：双击 `启动桌面歌词.bat`，或：

```bat
pythonw lyrics_overlay.py
```

**方式二（单文件 exe，推荐给没有 Python 的机器）**：双击 `dist\Desktop-sing-v<版本号>.exe`。
每次发版重新打包见下方「打包 exe」。**升级时不用先退旧版**：新实例会自动请求旧实例退出
（写 `restart.sig`，旧实例 ≤3s 内让位并带走自己的守护进程），然后无缝接管启动；
只有旧实例卡死无响应时才会弹窗要求手动退出。

启动后在 QQ音乐里播放任意歌曲即可。

**开机自启**：托盘 / 面板「系统」→「开机自启」打开即可（写入注册表 `HKCU\...\Run`，
走守护进程启动，开机后即使崩溃也能自动拉回）。也可以把 `启动桌面歌词.bat` 的快捷方式
放进 `Win+R` → `shell:startup` 打开的文件夹。

**进程保活**：同一处「进程保活」开关（默认开启）。开启后程序会拉起一个守护进程，
它先挂到当前进程的 PID 上持续监护；进程被强杀 / 崩溃时自动重启（退避 3s → 60s）。
从菜单点「退出」属于正常退出，会先写停机哨兵，守护进程随之下班。

## 打包 exe

产物：`dist/Desktop-sing-v<版本号>.exe`（单文件、无控制台；版本号自动取自 `lyrics_overlay.py` 的 `APP_VERSION`）。

Qt6/PySide6 需要 **PyInstaller 5+**（系统 Python 自带的是 3.6，太旧）。先建一次构建虚拟环境
（用 `--system-site-packages` 继承系统已装的 PySide6 / winsdk，不污染系统环境）：

```bat
python -m venv .buildenv --system-site-packages
.buildenv\Scripts\python.exe -m pip install -U "pyinstaller>=6"
```

之后每次发版只需一条命令：

```bat
.buildenv\Scripts\python.exe build_exe.py            :: 精简（默认，40.6MB）
.buildenv\Scripts\python.exe build_exe.py --full     :: 带全部内置字体（+15MB）
.buildenv\Scripts\python.exe build_exe.py --no-font  :: 不内置字体，体积最小（35.4MB）
.buildenv\Scripts\python.exe build_exe.py --dir      :: 产出 onedir 目录版（启动更快）
```

产物名带变体后缀，互不覆盖：默认 `Desktop-sing-v<版本>.exe`、`--no-font` 出的是
`…-lite.exe`、`--full` 出的是 `…-full.exe`。

`build_exe.py` 会自动收集 `fonts/`、`winsdk`（系统媒体控制 SMTC 后端）与 `Crypto`，并**排除
pywin32 整族**（本项目不用它；本机 pywin32 若装残，PyInstaller 的 pythoncom hook 会直接崩）。

### 体积

2.4.5 起做了瘦身，**72.8MB → 约 42MB**。单文件 exe 内部实际占用（用 `_diag_exe_size.py` 逐条量出来的，压缩后）：

| 内容 | 占用 | 说明 |
| --- | --- | --- |
| `winsdk._winrt.pyd` | 10.59 MB | 读系统媒体信息的 WinRT 绑定，**单个**扩展模块，少收子模块也省不掉 |
| Qt6 三个 DLL（Gui/Widgets/Core） | 9.19 MB | 已去掉 Qml/Quick/Pdf/OpenGL/Svg、软件渲染器 opengl32sw、Qt 翻译文件 |
| MiSans 内置字体 | 5.18 MB | 只带 Regular 一个字重，粗体由 Qt 合成；`--no-font` 可整个去掉 |
| PySide6 各 `.pyd` 绑定 | 4.29 MB | |
| python38.dll | 1.78 MB | |
| `PYZ.pyz`（全部业务代码） | 1.55 MB | |
| libcrypto-1_1 + libssl-1_1 | 1.55 MB | 网易云 weapi 签名用；Qt 那套 OpenSSL 3 已排除 |
| QtNetwork + 插件 + 其余 | 3.5 MB | |

已经试过但**收益不值得**的四条，记录在此免得重复踩：

- **字体子集化**：能省得多（GB2312 子集：7.75MB → 1.65MB，省 79%），但**不能用**。实测缺字时
  Qt **不会回退到系统字体，而是一个像素都不画** —— 歌词里的生僻字（如「龘」）会凭空消失，
  比出豆腐块更糟（用应用真实渲染路径量过：多一个生僻字，非零像素增量正好是 0）。
  想省这 5.2MB 只有 `--no-font` 一条路：整个不带，默认落到系统 Microsoft YaHei UI，
  用户可在设置面板一键下载 MiSans（下到 `%APPDATA%`，不占 exe）。
- **保留全部字形、只丢 GPOS/GSUB 等布局表**：只省 0.47MB，却伤拉丁文字距与连字 → 不做。
- **build 时用 `pyi-makespec.exe` 生成 spec**：这个 console-script 包装器在部分环境下会
  **静默失败**（退出码 1、零输出），导致「生成 spec → 注入 Qt 裁剪」整条链路被跳过、
  退回不带裁剪的打包，产物会从 40.6MB 涨到 60.6MB。现改为优先用
  `python -m PyInstaller.utils.cliutils.makespec` 调用，失败才回退到 .exe。
- **换 winrt-\* 细分命名空间包**（能省 `_winrt.pyd` 那 10.6MB）：这些包要求 **Python ≥ 3.9**，
  本机运行时是 3.8.6，换不了 → 不升级 Python 就没得谈。
- **去掉 winsdk 改用 ctypes 手搓 SMTC**：能省 10.6MB（约 25%），但要手写 WinRT 激活、HSTRING、
  三处 `IAsyncOperation` 回调 vtbl，任一偏移写错就是进程崩溃而非异常。它是「能不能读到歌」的
  核心链路，10MB 换稳定性是划算的 → 不做。

每次打包后历史产物会自动挪进 `dist\archive\`（不删文件），需要旧版本还能找回来。

### 性能（2.4.15 起）

三项都用工具量过，不是估算：

| 指标 | 优化前 | 现在 | 做法 |
| --- | --- | --- | --- |
| 冷启动到首帧 | 486 ms | **约 190 ms** | `winsdk`(~155ms) 与 `Crypto`(~80ms) 改为**延迟导入**：SMTC 绑定挪到采集线程里 import，主线程直接建窗；pycryptodome 等真走网易云接口时才 import |
| 抓歌词（冷缓存） | 约 1.3~2.2 s | **约 0.5~0.8 s（快 2~4 倍）** | 四个来源 QQ/网易云/酷狗/LRCLIB **并行竞速**，谁先到分高用谁；LRCLIB 从"顺序链路上最坏 12s"改成"只在缺逐字时才等，且卡 3s 上限" |
| 空转 CPU（窗口隐藏） | 1.6 % | **0 %** | 隐藏时整条帧定时器停掉，重新可见再恢复 |
| 空转 CPU（暂停静止） | — | **约 0 %** | 逐帧判断"画面到底有没有变"，静止状态不再空转重绘，定时器降到 250ms 巡检 |

> 量这三项的工具也在仓库里：`_diag_footprint.py`（启动/内存/CPU）、`_diag_fetch_latency.py`
> （抓词 A/B）、`_diag_exe_size.py`（体积构成）。它们踩过的坑写在脚本注释里
> （例如 `GetProcessTimes` 才够精度、`app.quit()` 之后窗口不再重绘会量出假的 0%）。

### 自检

打包好的 exe 没有控制台，怀疑它在某台机器上跑不起来时，加 `--selftest` 让它自己体检：

```bat
dist\Desktop-sing-v2.4.5.exe --selftest
```

会依次检查 Qt 能否初始化、SMTC 能否读到正在播放的歌、5 种样式能否渲染，结果写到
`%APPDATA%\Desktop-sing\selftest.txt`（末尾一行 `RESULT PASS` / `RESULT FAIL`），
崩溃信息写到同目录的 `fatal.txt`。整个过程 2 秒左右，不会常驻。

## 样式（5 种，右键/托盘/面板随时切换）

- **原生浮字**（默认）：歌词直接浮在桌面/窗口上，无底框，大字描边阴影，已唱部分随进度用封面主色渐变填色——和 QQ音乐/网易云自带桌面歌词一个观感
- **玻璃胶囊**：深色半透明胶囊底（底色随封面变化），带标题行、均衡器动画与进度条
- **iOS 音乐卡片**：借鉴 Apple Music 正在播放页——深色大圆角卡片、灰色小标题行、细进度条带圆点滑块、纯排版 + 1px 细描边
- **黑胶唱片**：左侧黑胶唱盘（33⅓ 转 1/8 速旋转，专辑封面做中心标签，同心唱纹 + 固定光泽带），右侧歌词 + 细进度线，播放时旋转、暂停即停
- **Spotify 声波**：借鉴 Spotify 播放条——近黑卡片、绿点「正在播放」上下文行、粗体当前句、底部细进度条

所有样式共用同一套主题系统：封面主色驱动、9 种逐字动画、字号/字体/透明度/边缘虚化设置全部生效。

**卡片特效策略统一为「原生浮字」那套（v2.4.13）**：五个主题一律不挂 `QGraphicsDropShadowEffect`。
该特效每帧都要把整窗渲染到离屏图再做多趟 16~26px 高斯模糊，在「无边框 + 半透明窗口」上
等于每帧多走一遍模糊与合成，是逐字动画被拖住的主因——原生浮字从 v2.4 起就是关掉它的那个主题，
所以只有它一直跟手。现在其余四个主题同样不吃每帧模糊，卡片靠自身渐变底 + 1px 描边与桌面分层。
要换回投影：把 `lyrics_overlay.py` 里的 `THEME_DROP_SHADOW` 改成 `True`。

其中**扇形展开**是把整行歌词从直线映射到一段圆弧上：每个字沿弧线就位并按切线方向旋转，
整行像折扇一样打开；**波浪起伏**用播放进度做相位让整行持续起伏；**弹跳落字**是从上方
落下并带回弹地放大到位；**打字机**则是硬切入字（不做渐变）。

## 视觉细节（v2.4.16 起）

### 质感统一：一套「光从上方来」的令牌（v2.4.18）

深色界面上，一块平板要读成「有厚度的面」，靠的不是加投影，而是三件事：

1. **顶部一条受光带**——卡片背景用渐变、头 4% 提亮（`UI_CARD_TOP`），模拟光从上方打下来；
2. **分层描边**——上边缘亮（`UI_EDGE_HI`，"接光"）、下边缘暗（`UI_EDGE_LO`，"落影"），
   左右中性（`UI_EDGE_MID`）。一条同样的 1px 描边，分了三档明度，物体立刻就立起来了；
3. **交互态反转受光**——按下时把顶部压暗、内部加深（读成"被按进去"）。
   旧版 `:pressed` 反而是换个**更亮**的底色，方向是反的（按下去更亮），读着别扭。

这些数值原先散落在各条 QSS 里各写各的，视觉语言不统一。现在集中成一组 `UI_*` 令牌
（文件顶部），面板 / 控件 / 菜单 / 浮层共用同一套「光从上方来」的假设：

| 令牌 | 值 | 用途 |
|---|---|---|
| `UI_CARD_TOP` / `UI_CARD_BODY` / `UI_CARD_BOT` | `#242935` / `#1b1f28` / `#13161c` | 卡片三段渐变（受光带 / 主体 / 落影） |
| `UI_CTRL_TOP` / `UI_CTRL_BOT` | `#272c38` / `#1b1f27` | 按钮、下拉的渐变 |
| `UI_EDGE_HI` / `UI_EDGE_MID` / `UI_EDGE_LO` | `rgba(255,255,255,36)` / `rgba(255,255,255,20)` / `rgba(0,0,0,80)` | 上 / 左右 / 下 描边 |
| `UI_GROOVE` | `#080a0e` | 凹槽（滑块轨道 / 分段轨道）打底 |
| `UI_R_CARD` / `UI_R_CTRL` / `UI_R_ICONBTN` | 14 / 9 / 11 | 圆角阶梯 |

配套的控件侧改动：

- **头部控制键**从棱角分明的硬边框方盒，改成「半透明填充 + 大圆角」的软图标按钮；
- **分段选择器**的选中滑块加了落影 + 主色竖向渐变（读成浮在槽上的实体块），
  未选中项响应悬停提亮（给点击预期）；
- **开关**轨道改竖向渐变（顶暗底亮 = 有深度的槽），圆钮加一圈落影；
- **滑块**轨道做成凹槽、圆钮加 1px 暗环（白钮在亮底上没环会糊进背景）；
- **面板打开时不再把焦点落在第一个按钮上**（原来首个按钮一开面板就顶着焦点描边，
  看着像"预设选中了某个操作"）；焦点收回面板本身，Tab 仍可在控件间走。

### 逐字卡拉OK：硬切 → 柔性波前（v2.4.18）

旧版逐字高亮是**整字一个平色**：正在唱的那个字显示成"未唱白"和"已唱主色"之间的一档中间色，
所以视线扫过去是「一格一格跳」，那个字还会突兀地跳出来。

现在正在唱的那个字沿**字宽**铺一条横向渐变，端点落在 `e±0.5`（`e` 是该字的演唱进度），
相邻字的渐变互相搭接，整行读起来就是一道**连续推进的波前**。方向不能搞反：
波前从字左往右推进，所以左端是已唱、右端是未唱——这一条回归测试专门盯着
（`smoke_test.py [30]`：取活动字左 18% / 右 82% 两处的墨色绿通道，主色的绿通道远低于未唱白，
所以「左 < 右」才说明波前方向对）。`typer`（打字机）风格仍走硬切，保持原本的机械感。
开关是 `KARAOKE_SOFT_EDGE`，留它是为了能出 A/B 对照（`_diag_karaoke_ab.py` → `preview/karaoke_ab.png`）。

### 菜单图标列（v2.4.18）

菜单项从纯文字加上了图标列（设置 / 播放控制 / 重新获取 / 退出…），一眼能扫出类别。
图标在**选中态自动换深色**——选中行是主色填充，浅灰图标压上去会糊成一片；
`make_menu_icon()` 把两张不同颜色的位图分别挂到 `QIcon.Normal` 与 `QIcon.Selected` 模式上，
一个 QIcon 同时满足两种底。托盘菜单是常驻对象、不重建，所以播放/暂停那一格的图标
在 `_sync_tray_menu()` 里跟着状态刷新。

### 悬停控制条避让 + 首句入场落点 + 胶囊白块（v2.4.19）

三个用户实测报上来的显示 bug，根因都不在"画歪了"，而在**布局/绘制状态根本不知道另一方的存在**：

**① 悬停控制条直接画在歌词上。** 白色胶囊锚死窗口右下角（`_ctrl_rect`），而窗口高度
只由内容决定、悬停时完全不让位 —— 胶囊 212×36 又不随字号缩放，必然压住下一句歌词，
进度条和时间文本也躲不开。修法：悬停时窗口底部为胶囊**预留一行**（`_ctrl_reserve()`），
进入悬停先把窗口加高（300ms 尺寸动画）、胶囊再淡入，它一出现就已经在自己的行里；
离开时等胶囊完全淡出**之后**才收回预留行（避免叠在歌词上淡出）。五套样式的卡片
改从统一的 `_content_rect()` 取几何（悬停让出的那条就是胶囊的位置），黑胶的内容中线、
原生样式的封面居中也都改成基于内容区，悬停加高时不再错位。贴边预设通过 `resizeEvent`
跟着新尺寸重新落位——加高的几十像素朝屏幕内侧长，不往任务栏方向顶。
**无卡片样式（原生浮字 / 黑胶）的下一句歌词不透明度同时上调**（172/176 → 200/204），
浅色壁纸上读得清了。回归：`smoke_test [32]` 对五种样式断言「胶囊 ∩ 内容区 == ∅」，
并带变异自检（把预留行归零 = 旧行为，断言必须被触发）。

**② 第一句歌词的动画被画到歌名行上。** 前奏期（播放位置还没到第一句）主循环把
`cur_idx` 提前置 0 而 `current` 留空 —— 当前行显示歌名回退文本，第一句挂在"下一行"。
等播放真正越过第一句时间轴时行号仍是 0，旧版**只比较行号**，第一句永远进不了当前行：
进度填色被套在歌名回退文本上（截图里金色的「♪ 歌名」就是这么来的），然后整句被跳过。
修法：触发条件加上「文本变了」；同时五种样式的卡拉OK分支要求 `_current_text` 非空
（前奏期只画歌名/占位的素文本）。连带修掉两处同源问题：换歌 / 重新获取歌词时只归零
行号、不清 `_current_text/_next_text`，上一首的最后一句会画在新歌的歌名位置上
（统一走 `_reset_line_state()`）；玻璃样式的标题行 alpha 绑了 `_line_t`，每切一次行
标题就跟着闪一下（改常量）；前奏期不再把第一句的翻译垫在占位下面。

**③ 控制条胶囊被填成实心白块（"菜单显示异常、可读性差"）。** 这一条和 ① 是同一张
截图里的两个症状：胶囊**压住歌词**是布局问题，**糊成白块**则是画笔状态泄漏。
`_draw_progress()` 画完进度条末端的白色滑块后没有复位画刷，而 `_paint_controls()` 用
`drawPath(bg)` 画 1px 边框 —— **`QPainter.drawPath()` 会顺带用"当前画刷"填充路径**，
于是本该只是描边的调用把整条胶囊涂成了 `#ffffff`（离屏取样：只填充 = `#171920`，
填充+描边 = `#ffffff`）。修法两层：① `_draw_progress()` 整体 `save/restore` 兜底，
不再往上游漏画笔；② 新增 `_stroke()` 统一在描边前强制 `NoBrush`，五处"fillPath 后
紧跟 drawPath 描边"的卡片/胶囊绘制全部改走它 —— 任何上游再漏有色画刷都影响不到描边。
回归：`smoke_test [32]` 对五种样式**取样胶囊像素**断言"是深色玻璃而非亮块"（含变异
自检：把 `_stroke` 换回不复位画刷的旧行为，断言必须翻车）。
> 悬停这套预留行机制随后又暴露出**进出场抖动**（胶囊跟着窗口底边滑走 + 透明像素穿透
> 触发假离开），在 v2.4.20 单独修，见下节。

### 悬停乱跳：胶囊滑走 + 透明像素穿透（v2.4.20）

v2.4.19 修完可读性后，用户实测：**悬停时控制条（连同窗口）反复上下跳动**。可读性没问题了，
但鼠标一悬上去，胶囊就不停在"出现→消失→再出现"。两个因素叠成的进出场死循环：

1. **胶囊锚在窗口底边**。悬停时窗口要往下长高 48px（300ms 尺寸动画），胶囊跟着底边
   一路向下滑走 —— 鼠标原本指着的位置在动画结束后变成空。
2. **半透明分层窗口是逐像素命中的**（Windows 对 `WS_EX_LAYERED` 窗口按像素 alpha 做命中
   测试，alpha=0 的像素直接穿透给下层窗口）。于是：光标指着胶囊 → 窗口加高、胶囊滑走 →
   光标底下变成透明像素 → OS 判定"已离开窗口"、发 `leaveEvent` → 胶囊淡出、预留行收回 →
   光标又指回胶囊 → `enterEvent` → 再加高…… 无限循环。另外鼠标从内容移向胶囊时要跨过
   中间的透明间隙，同样会触发一次"假离开"。

**修法（两处）**：

- `_ctrl_rect()` 改锚**内容区下缘 + 6px**，不再锚窗口底边。内容区在悬停前后的几何完全
  一致（顶部固定、高度不变），所以胶囊从出现到消失在屏幕上一个像素都不动 —— 抖动的
  "位移"源头被掐掉。
- `leaveEvent` **不再触发淡出**，淡出改由 `_on_frame` 轮询全局光标位置
  （`_cursor_global()`）触发：光标真的出了窗口矩形才开始收胶囊。落在透明间隙上的
  "假离开"直接无视 —— 消除"跨间隙必抖"的另一半。光标在悬浮层边界附近来回时，
  胶囊保持可见（比原来"碰到间隙就消失"的手感也更合理）。连带：`hideEvent` 复位悬停态，
  避免再次显示时带着一块未淡出的旧胶囊。

回归：`smoke_test [32]` 新增「悬停加高不挪胶囊 / 光标轮询防抖」—— 断言悬停加高前后
胶囊与内容区的屏幕坐标完全不变、光标在窗口矩形内不触发淡出 / 真出矩形才收；
变异自检把 `_ctrl_rect` 换回"锚窗口底边"的旧行为，断言必须翻车。原「hover 控制条
不压内容」的变异探针也同步升级为完整复现旧行为（锚回底边 + 预留行归零）。

### 悬停时卡片塌陷 / 胶囊被切（v2.4.21）

用户第三轮反馈：**iOS 主题（整块实心卡片）悬停时明显塌陷一下，控制条还被切掉一截**。
根因是内容几何被"窗口正在动画的高度"污染了：

`_content_rect()` 原本由**当前窗口尺寸反推**（`h - 2*margin - reserve`）。悬停触发的那一帧，
窗口还是旧高度（150px），而 `_ctrl_reserve()` 已经生效（48px）→ 内容区瞬间被切掉一整行：

| 加高进度 | 旧：窗口高 | 旧：卡片高 | 新：卡片高 |
|---|---|---|---|
| 0% | 150 | **62**（塌陷 −48） | 110 |
| 50% | 192 | 95 | 110 |
| 100% | 198 | 110 | 110 |

卡片先塌陷再随 300ms 动画弹回来，胶囊锚在卡片下缘跟着上下滑，加高到 45% 之前还会被
窗口下边切掉一截 —— iOS/Spotify/玻璃这三种卡片主题上特别扎眼（黑胶是内容中线在跳）。

**修法**：
- **`_relayout()` 存下 `_layout_size = _pill_size()`，`_content_rect()` 只认这份几何**，
  与窗口尺寸动画彻底解耦。加高/收回全过程卡片高度恒定，胶囊顶也恒定（实测 0%~100%
  卡片高都是 110.0、胶囊顶都是 136.0）。
- **胶囊淡入延后 150ms**（`QTimer.singleShot` + 仍在悬停才淡入）：等那一行真正长出来
  再出现，视觉上是"先让位、再出现"，不再先冒出半个再滑出来。窗口已够高时（比如反复
  进出）立即淡入，不引入无谓延迟。
- `preview_render.py` 三处手工 `resize()` 改走新增的 `_relayout_instant()`：预览脚本没有
  事件循环，原先自己按 `_pill_size` 算尺寸，会绕过 `_layout_size` 与真实观感分叉。

回归：`smoke_test [32]` 新增「加高动画不压内容（无塌陷）」—— 在尺寸动画 0/25/50/75/100%
五个进度上断言内容区宽高恒定；变异 = `_content_rect` 换回按窗口高度反推，断言必须翻车。

### 前奏期"第一句不显示"：第一句直接进当前行（v2.4.22）

用户第四轮反馈：前奏期当前行显示**"♫ 纯音乐或暂无歌词"**、第一句缩在下一行小字里，
看起来就像"第一行歌词丢了"。

根因有两层：
1. **误导性回退文案**。玻璃样式在 `_current_text` 为空时一律显示"纯音乐或暂无歌词"，
   哪怕歌词明明存在、只是还没唱到（前奏/间奏）。其余四种样式回退到歌名，只有玻璃
   回退到占位。
2. **前奏期的排布本身就别扭**。v2.4.19 的设计是"前奏期当前行显示歌名/占位回退、
   第一句挂在下一行小字里，唱到才升入当前行"——句子在 27 秒前奏里一直躲在角落，
   用户自然认为它没显示。

**修法（对齐 Apple Music 的做法）**：
- **前奏/间奏期第一句直接放进当前行、下一行挂第二句**（`_prelude_texts()`）。逐字
  进度本来就是按 `pos` 实时计算的（无状态），此刻自然全暗、无填色，唱到哪个字哪个
  字亮 —— 不需要任何额外状态。第一句的入场动画改在**歌词加载完成时**播（行升入
  位置），唱到时行已在位、不再重播。
- 当前行为空时的回退文案改为**按情况区分**（`_idle_current_text()`）：有歌词但还没
  唱到 → "♪ 歌名"；真没歌词 → "♫ 纯音乐或暂无歌词"。占位文案从此只出现在真没歌词
  的歌上。
- 附带收益：旧设计在前奏期按回退文案估宽、唱到第一句时胶囊宽度会跳一下；现在
  前奏期就按第一句真实文本布局，不再跳。

回归：`smoke_test [32]` 重写「首句入场落点」—— 前奏期断言 `(cur_idx, 当前, 下一)
== (0, 第一句, 第二句)`、卡拉OK 以第一句渲染、占位文案与下一行小字都不许出现；
唱到时不重播入场动画；变异 = `_prelude_texts` 换回旧行为（当前行空）必须翻车。
新增「纯音乐占位只在真没歌词时出现」。开发中测试还当场抓到一次改错：`_idle_current_text()`
被误当成当前行文本用（漏了 `_current_text or` 前缀），玻璃样式会永远画回退文案 ——
断言 `karaoke_texts == ["第一句歌词"]` 直接拦下。

### 窗口被屏幕边缘裁掉 / 控制条"长到屏幕外"（v2.4.23）

用户第五轮反馈（经确认是同一个根因的两个症状）：
1. **卡片/窗口被屏幕边缘裁掉一块** —— 自由摆放的窗口停在屏幕工作区边缘外
   （拖出来的，或换显示器/改分辨率后恢复到了看不见的旧坐标）；
2. **悬停控制条有问题** —— 悬停为控制条加高的 48px 固定朝窗口下方长，窗口贴着
   屏幕下缘时这一行直接落到屏幕外，控制条永远出不来。

v2.4.19 的贴边预设重新落位只管预设摆放（`free` 明确不动），自由摆放没有任何屏内
约束 —— 这是缺口。

**修法：新增 `_clamp_into_screen()`，把窗口整体夹回所在屏幕的工作区
（`availableGeometry()`，自动避开任务栏）**，挂在这些时机上：

| 时机 | 覆盖的场景 |
|---|---|
| `resizeEvent`（每次尺寸变化） | 悬停加高/收回、切主题、字号变化 |
| 拖拽中（`mouseMoveEvent`）+ 松手 | 拖不出屏幕外，也不会留一半在外面 |
| `showEvent` | 隐藏期间显示器变了 |
| `_restore_position` | 配置里存的旧坐标在屏外（换显示器/分辨率） |

预设位置本来就按工作区计算，夹屏对它们是无操作。窗口比工作区还大时（超大字号 +
小屏）退到工作区左上角。

回归：`smoke_test [32]` 新增「窗口夹回屏幕工作区」—— ① 单元：屏外窗口被拉回；
② 集成：贴着工作区底缘悬停加高后，窗口底与控制条底都不得越过工作区；③ 收回后仍
完整可见；变异 = 禁用夹屏后同样的悬停加高必须把窗口顶出工作区。37 组全过。

### 控制条"只展开一半" / 悬停状态随机卡死（v2.4.24）

用户第六轮反馈：控制条还是只展开一半，且随歌词长度变化（换行）有时整个悬停
展示卡住。前四轮修复（锚定、轮询防抖、几何解耦、夹屏）都是必要的，但都没碰到
真正的扳机。

**根因（探针 `_diag_ctrl_stuck.py` 用真实时间泵逐帧采样抓到）**：
`QVariantAnimation` 在 `setEndValue()` 里就会**同步发出一次 `valueChanged(起始值)`**
——此时动画 state 还是 Stopped、一帧都还没跑。淡入从 `ctrl_t=0` 启动时这个值
就是 **0.0**，而 `_on_ctrl_anim` 里 `v <= 0.0 and self._hovered` 把它误判成
「淡出结束」→ 复位 `_hovered` → `_relayout()` 收回 48px 预留行。于是：

- **窗口塌回矮高度、胶囊却淡到全不透明**：36px 高的胶囊被窗口裁得只剩约 6px
  ——「只展开一半」；
- 换行触发 `_relayout` 重启 300ms 加高动画时，脉冲落点随相位漂移，状态机走到
  各种中间态 ——「随歌词长度变化有时卡住」。

**修法**：`_animate_ctrl()` 装弹期间（stop → setStartValue → setEndValue →
start）置 `_ctrl_setting_up` 抑制标志，这段窗口期发出的 `valueChanged` 一律视为
启动脉冲忽略；真实 tick 与直接调用不受影响，淡出结束照常收回预留行。

回归：`smoke_test [33]` —— 走 enterEvent 真实路径（enter → 加高动画 Running →
延迟淡入 → 淡入播完），断言悬停态不丢、窗口不塌回、胶囊完整落在窗口内；再走
一遍正常淡出确认预留行仍会收回。变异 = 换回「装弹不设抑制标志」的旧
`_animate_ctrl`，悬停态断言必须翻车。

### 控制条左端被窗口裁掉（v2.4.25）

用户第七轮反馈：胶囊左侧的「上一首」按钮被裁掉半格、左圆头消失。

**根因**：胶囊宽 `6*CTRL_CELL+8 = 212px` 固定、不随字号缩放，而各主题的窗口
最小宽都比它窄——原生浮字「短歌词 + font_scale 0.7」只有约 **202px**（`block`
下限 `_px(220)`=154 + 边距）、ios 约 207px、spotify 约 234px。`_ctrl_rect()` 按
`width - m - 212` 右锚定，窄窗下算出**负的左边**，胶囊左端被窗口裁掉。

**修法（双保险）**：
1. `_relayout` 悬停时窗口宽度保底 `_ctrl_min_window_w()`（胶囊宽 + 左右各
   4px），由 300ms 尺寸动画顺带加宽；收回悬停后照旧缩回，非悬停观感不变；
2. `_ctrl_rect` 把矩形夹回窗口内（右贴边距优先、左至少 4px）兜底，任何窗口
   宽度下左端都不为负。非悬停的窄窗物理上装不下胶囊，但此刻胶囊透明度为 0
   且不参与命中（`_ctrl_t < 0.5` 直接判空），露头无害。

回归：`smoke_test [34]` —— 原生短句 + 小字号构造 202px 窄窗，断言悬停时窗口
≥ 保底宽、胶囊两端都落在窗内、收回后窗口复原；变异 = `_ctrl_min_window_w`
归零后右侧出窗断言必须翻车。

### 文字描边：从「实心粗描边」改为「双层柔和落影」

以前非 iOS 主题用的都是单层 `QPen(黑, alpha=170, w)`。实测它在**浅色壁纸**上会糊成一圈
厚重的黑边、字看着发脏；而 iOS 主题一直是 `halo_on=False`，反倒最耐看。

现在改成两层（`LyricOverlay._halo_pens`）：**外层宽而淡**负责把字从壁纸上「托」起来，
**内层细而深**负责边缘清晰度。参数按背景分两档：

| 情形 | 样式 | 描边 |
|---|---|---|
| 无卡片底（文字直接压壁纸） | 原生浮字 / 黑胶 | `HALO_BARE`（较明显） |
| 半透明卡片（壁纸会透上来） | 玻璃胶囊 | `HALO_CARD`（极淡） |
| 接近不透明卡片 | iOS / Spotify | 不描边（`halo_on=False`） |

未唱到的字的不透明度也跟着分档：无卡片样式要给足（`DIM_BARE`），否则在浅色壁纸上读不出来。

**代价**：有描边的三套每帧 +0.33~0.45ms（多一次 `strokePath`），最慢 2.04ms / 33ms 预算。
iOS/Spotify 本来就没描边、耗时不变——这个对照正好确认增量就是那次多出来的描边。

**调参必须两种底色一起看**：`preview_render.py` 现在对每套样式同时输出浅色与深色桌面两版。
只对着一种底色调，很容易调成「只适合这一种壁纸」——第一版把外层设成 `w*1.95 @ alpha 52`，
在深色壁纸上完美，在浅色壁纸上就是一片灰雾。`_diag_halo_ab.py` 提供四宫格对照图。

### 设置面板

- **下拉箭头**：Qt 的 QSS **不支持** CSS 三角写法（`border-left: 4px solid transparent` 那套），
  写了不报错但会渲染成一个小方块。改为运行时用矢量画一张 chevron 落到配置目录、再让 QSS 引用
  （`combo_arrow_url()`，文件已存在则复用）。
- **卡片**：纯色填充 → 极淡纵向渐变，读起来像「微微受光的面」，不再是一块死板的色块。
- **分区标题**：主色文字 + 左侧 3px 主色竖条，一眼能定位分区。
- **分段选择器轨道**：原来 `#181b22` 和卡片底（`#1c2029~#14171e`）几乎同色，轨道整个糊进
  卡片里、看着像选项在飘；改成明显更深的 `#0a0c11` 才读得出「凹槽」。
- **屏保入口按钮**：从通栏高饱和主色降级为描边式——屏保本身只是个可逆展示态（上方缩略图
  也能点进去），做成"危险操作"的红条并不合适。
- **屏保缩略图圆角**：QLabel 的 `border-radius` 只圆它自己的背景、**不会裁**画进去的 pixmap，
  所以圆角要用 `round_pixmap()` 画在 pixmap 上，否则是「圆角框里塞了张方图」。
- 滑块圆钮 15px → 14px：15px 配 radius 8 在 Qt 里渲染成圆角方块，14px 配 radius 7 才是正圆。
- **无焦点/禁用态补齐**：`QPushButton:focus` 用主色描边、`:disabled` 降成灰字浅边——不然键盘/禁用状态下按钮和普通态一模一样，看不出区别。
- **下拉列表项**：`QComboBox QAbstractItemView` 加 `selection-color` 与逐项 padding/圆角，弹层里的高亮条不再顶到边缘。

### 菜单与弹层：一次把「漏成原生白底」的坑全补上（v2.4.17）

深色皮肤只写在设置面板上是**不够**的——菜单、下拉弹层、对话框都是**顶层窗口**，
各自继承不到面板的 QSS，会悄悄退回 Qt 默认的浅色控件模样。这轮把它们逐个查了一遍：

- **右键菜单**：`_show_menu` 里漏了 `setStyleSheet(menu_qss(...))`，弹出的其实是**系统原生白底菜单**。
  现在把菜单构建拆成 `_build_context_menu()`（纯构建、可断言），`_show_menu` 只负责 `exec()`——
  这样回归测试能直接拿到菜单对象，断言它确实套了皮肤（见 `smoke_test.py [29]`）。子菜单会继承父菜单的样式表。
- **菜单字体**：`menu_qss` 原来漏了 `font-family`。菜单是顶层窗口不继承面板字体，中文会渲染成**方框**（豆腐块）。
  补上 `"Microsoft YaHei UI"` 后与面板一致。
- **下拉弹层白边**：`QComboBox` 的下拉是个 Qt **私有** `QFrame` 子类 `QComboBoxPrivateContainer`，
  深色的内层 `QAbstractItemView` 外还包着一圈白边。只有**类名选择器**命得中它——
  裸选择器和 `.QFrame`（子类）都匹配不到。`fix_combo_popup()` 给每个下拉的弹层套一条
  `QComboBoxPrivateContainer { background: transparent; border: none; }`。
- **对话框**：`QMessageBox.about()` / `.warning()` 的**静态方法**是系统原生白底弹窗，不继承任何皮肤。
  换成自制的 `build_message_box()` / `styled_message()`（暗底 + 主色按钮），「关于」与「升级接管」提示都已改走这条路径。
- **菜单图标**：子菜单右侧箭头与勾选标记统一改用运行时画的 PNG（`ui_icon_url("menu_arrow" / "menu_check")`）——
  原因同下拉箭头：Qt 的 QSS 画不出 CSS 三角，只给宽度会退回系统原生小三角，和自制 chevron 风格对不上。

预览：`preview_render.py` 增出 `menu.png`（主菜单 + 子菜单）与 `dialog.png`，
把深色菜单/对话框铺在浅色桌面上，**一眼就能看出有没有变白**。

### 版式：遮挡是「结构上不可能」，不是调参凑出来的

`AmbientSaver._plan()` 是屏保**唯一的版式来源**，`paintEvent` 与回归测试读同一个函数，
所以「断言不重叠」和「画出来不重叠」是同一件事，不会各算各的然后悄悄漂移：

1. 先量出文字块的**真实高度**（`QFontMetrics`），再在文字区里定位；
2. 动画另占一条**动画带**，与文字区之间留 `ZONE_GAP`，两者在构造上不可能相交；
3. 绘制动画时 `setClipRect(动画带)` —— 就算动画在数学上画到了带外，也压不到文字。

三条加起来，遮挡是被结构杜绝的。版式常量集中在 `_plan` 上方：

| 常量 | 作用 |
| --- | --- |
| `SAFE_X` / `SAFE_Y` | 文字与屏幕边缘的最小边距；长歌词的省略号截断宽度也在这里算 |
| `ZONE_GAP` | 文字区与动画带之间的最小空隙 |
| `TRAVEL_MIN` | 文字区里**必须**留给 AOD 换位的比例（防烧屏的底线） |
| `TEXT_MAX_H` | 文字块高度上限（占 `min(w,h)`）—— 锁住跨风格的时钟尺寸一致性 |
| `ANCHOR_HOLD` / `ANCHOR_MOVE` | 纵向换位（顶/中/底三档）的驻留与过渡秒数 |
| `DIM_START` / `DIM_RAMP` / `DIM_FLOOR` | 长时间空闲后的渐进变暗（显示器 ASBL 的软件版） |

自动适配走三级退路：**① 缩字号把 `TRAVEL_MIN` 的换位行程让出来 → ② 缩到能塞进整个文字区（不丢行）
→ ③ 按重要度丢行（next → date），永远保住 clock + lyric**。
面板缩略图（252×142）走紧凑模式，只放 clock + lyric —— 空间不够时该让位的是日期，不是歌词。

### 两处真实修过的坑

- **AOD 换位曾经等于没写**：4 行版式在 16:9 上正好把文字区填满（`block_h ≈ tz_h`），
  换位行程只剩 **0.1px** —— 换位代码在跑，却一点位移都没有，防烧屏悄悄失效，
  而当时所有测试都是绿的。现在 `TRAVEL_MIN` 强制让出行程（1920×1080 下 particle 143px），
  并且有专门的断言 + 变异自检守住它。
- **动画带边界有一条可见接缝**：光晕原来写 `fillRect(带, 圆渐变刷)`，圆的半径按带的长边算，
  到带的上下边时渐变还远没衰减到 0，一刀切下去留下 **6~13/255** 的亮度阶跃，浅色壁纸上尤其明显。
  现在改成先把画布纵向压扁、再填一个**内切椭圆**，四条边中点与四个角的 alpha 精确为 0，
  接缝在数学上就不存在（实测阶跃 0.00）。

**为什么元素要整体游移，而不只是自转**：星云核心、星轨圆心只绕自身中心旋转 ——
像素的**平均位置**没变，占空比照样接近 1。所以三种动画风格共用一个极慢的双轴 Lissajous
游移中心（周期 257s / 173s，振幅压到带宽 5.5% / 带高 11%），音条排也横向跟着走
（竖直不动，否则像画面在抖）。实测把 particle「半程以上都在亮」的面积从 27.5% 压到 15.2%。

| 脚本 | 查什么 | 用法 |

### 巡检脚本共用的配置沙箱（`_cfg_sandbox.py`）

`smoke_test.py` 与三个巡检脚本都要**临时改写** `%APPDATA%\Desktop-sing\config.json`
（换成「关热键 / 关保活 / 关屏保」的固定桩），否则跑一次就会去抢全局热键、拉起守护进程、
覆盖用户设置。这段逻辑原先各写各的，踩了三个坑，现已统一到 `_cfg_sandbox`：

| 坑 | 现象 | 现在的做法 |
| --- | --- | --- |
| 备份路径撞车 | 三个脚本共用 `config.json.prevbak`，并行跑时先结束的把备份 `os.remove` 掉，后结束的还原时 `FileNotFoundError` → 断言全过却以**退出码 1** 收场 | 备份路径按脚本名区分（`config.json.prevbak.<脚本名>`） |
| 备份备到别人的桩 | 就算不崩，后启动的一方可能把「前一方刚写下的临时桩」当用户配置备份，还原后**用户的真实配置被假配置顶掉** | 一把跨进程锁（`config.json.sandbox.lock`），短等 → 超时抢占，把并行变成正确串行 |
| 异常退出走不到还原 | 被 SIGTERM（跑太久超时）时还原代码在文件末尾，压根执行不到，配置永久停在临时桩上 | 还原注册到 `atexit`，并接管 SIGTERM / SIGINT，被杀之前先把配置还回去 |

收尾一律以 `atexit` 兜底 + 显式 `restore()` 双保险，且**还原失败只吞异常、绝不抛**
（诊断脚本的退出码只应表示「断言过不过」，不该被配置收尾问题污染）。
残留锁（上次被 kill 留下的）按**持有进程是否还在**立即抢占，pid 读不出来时才退回 mtime 判定
—— 只按 mtime 判会白等整个等锁超时（实测踩过：持有进程早已消失，却因为锁文件「不够旧」
让下一次运行干等 90 秒）。所以不会留下永久死锁。

> 巡检脚本请**串行跑**。现在并行也不会搞坏配置（会打印等锁提示、自动排队），
> 但排队意味着没有真正并行，徒增等待。确实需要绕过锁时设 `_CFG_SANDBOX_NO_LOCK=1`。

万一巡检崩溃后配置已被临时桩顶掉，一条命令收拾残局：

```bat
python -c "import _cfg_sandbox; _cfg_sandbox.reset()"
```

「巡检不许搞坏用户配置」这件事本身也有回归用例（`smoke_test.py [31]`）：
临时目录里跑完整的加锁 / 备份 / 还原往返，断言备份路径按脚本名区分、
往返一字不差、备份被删时不许抛、原本无配置时不许留下临时桩、
残留锁按 pid 存活**立刻**抢占（而不是白等超时）、pid 读不出来时退回 mtime 判定、
真有人在跑则等满超时而不是硬闯。

## 稳健性

- **长句自适应**：一行歌词过长时按 5% 逐级缩小字号（最低 55%），仍放不下才截断
- **SMTC 快照外推（v2.4.9 起，根治"卡住"）**：SMTC 的 `TimelineProperties.position` 只是「`last_updated_time` 那一刻」的快照，QQ音乐/网易云经常几十秒不刷新这条时间线。旧版直接把快照当实时进度，播放器一停更歌词就冻结。现在监听层按 Windows 自己的算法换算实时进度：`position + (now - last_updated_time)`（仅 PLAYING 时），下游永远看到平滑前进的进度
- **锚点外推 + 冻结免疫（真平滑来源）**：下游 `_apply_tick` 用锚点外推 `anchor_pos + (time.monotonic() - anchor_ts)` 把两次 tick 之间的进度平滑出去；`status != PLAYING` 时位置冻结是系统**正确行为**（缓冲/设备切换/抢占/静默暂停都会把会话置 Paused），绝不外推；`last_updated_time` 为 0 / 负数 / 未来时间等脏 FILETIME 也兜底返回原始值，不跳变
- **幽灵会话规避（v2.4.10）**：会话选择从"取第一个"改为按活跃度排序（正在播放 > 音乐类 App > 同源 sticky > 时间线更新鲜），QQ音乐崩溃残留的死会话会被避开；检测到 AUMID 切换时强制复位歌词数据并重锚外推基准
- **会话健康日志**：约 20s 一次记录 `AUMID / status / raw_pos / age / 外推值`，冻结事件也带上 `status`——卡顿时看日志即可一锤定音：是"真 Paused（系统行为）"还是"幽灵死会话"还是"数据层冻结"
- **上报冻结免疫**：作为快照外推的安全网——若播放器上报仍冻结（音乐在放、位置不动），检测到就直接忽略上报、继续本地外推，快进/拖动/大幅回退仍会正常跟随，事件会记入日志
- **渲染保护**：单帧绘制异常只记录日志并降级，不会拖崩程序
- **单实例守护 + 升级自动接管**：重复启动时新实例会写 `restart.sig` 请求旧实例让位并等它退出（≤8s），成功则无缝接管启动；旧实例守护进程收不到诈尸机会（停机哨兵先写）；等不到才弹窗提示手动退出旧实例
- **热键不抢焦点 / 不阻塞**：全局快捷键跑在独立消息循环线程里，命中后跨线程发信号回主线程处理；组合键被占用时自动跳过并明确提示，不会静默失效；关闭再打开是**同步注销**，不会出现抢占竞态
- **动画时间积分**：黑胶旋转、光晕呼吸按真实时间积分，帧率变化（33ms ↔ 100ms ↔ 150ms 动态降频）不会导致动画忽快忽慢
- **主题不吃每帧重特效（v2.4.13）**：五个主题统一为"不挂 `QGraphicsDropShadowEffect`"（原生浮字从 v2.4 起就是这套逻辑）。离屏实测 5 个主题均为 1.6~2.5ms/帧、最长帧间隔 <60ms、零卡顿，逐字动画在哪个主题都不会被模糊拖住；改主题只影响配色与排版，不影响动画手感。用 `_diag_theme_perf.py` 可随时复测每种主题的每帧耗时与帧间隔
- **歌词引擎不外泄脏数据（v2.4.14）**：所有来源的歌词在返回前统一过一遍 `clean_lyrics()`（含缓存读路径），信息行 / 制作名单 / 重复时间戳一律拦在渲染之前——实测「起风了」从 69 行（首行是`小提琴：须磨和声`）收敛到 64 行纯歌词；制作名单识别要求「角色 + 冒号（或整行只有角色）」，因此 `鼓起勇气` / `曲终人散` / `录音机里放着老歌` 这类正常歌词一个都没被误伤
- **摆放位置不写死坐标（v2.4.14）**：预设位置在每次启动时按**当前**屏幕安全区重算（`availableGeometry()`），换了显示器 / 调了任务栏 / 改了缩放都不会跑到屏幕外；手动拖拽后自动标记为「自由摆放」，预设不会再把窗口拽回去
- **配置容错**：新版本读取旧缓存自动降级（缓存格式带版本号），旧配置缺字段走默认值
- **进程保活不诈尸**：守护进程先挂到当前 PID 上监护（不会另起实例撞单实例守卫）；正常退出写停机哨兵 + 退出码 0，守护进程据此收工；崩溃才退避重启
- **字体下载不阻塞 UI**：下载跑在后台线程，进度通过 Qt 信号回主线程更新按钮；下载失败只是按钮变「重试」并提示，不会拖崩面板
- **全屏屏保可安全退出**：`setWindowFlag` 之后一定补 `show()`（Qt 会隐式隐藏窗口），键鼠输入即退
- 配置实时保存；托盘菜单每次弹出自动刷新勾选状态
- 不依赖 emoji 字体：控制条 6 个图标、锁、齿轮、月亮、下载态全部矢量绘制，避免不同机器出现方框

## 工作原理

1. `winsdk` 监听 Windows **GlobalSystemMediaTransportControls**（就是任务栏媒体弹窗用的那套），每 0.5s 轮询歌曲与进度；网易云（cloudmusic）与 QQ音乐都在优先列表里，多个播放器同时开着时跟随"正在播放"的那个，避免来回跳；
2. 换歌时按"标题 + 歌手"搜索：网易云走网页版 **weapi 加密搜索**（AES×2 + RSA，未登录的老接口结果全是翻唱不能用）+ 歌词接口，QQ音乐走 `musicu.fcg` 搜索 + LRC 接口，**酷狗**走 `mobilecdn` 搜索 + `lyrics.kugou.com` 取 KRC（base64 → 异或 → zlib 解密，逐字轴直接可用）；候选按"歌名+歌手"加权匹配，避免拿到翻唱歌词。各来源结果**先算质量分再择优**（逐字 > 翻译 > 行数 > 末行贴合歌曲全长），拿到「逐字+翻译」就提前收工；都没命中时用 [LRCLIB](https://lrclib.net) 的候选补位；
3. 翻译歌词与原文同批取回（QQ 歌词接口的 `trans` 字段 / 网易云 `tlyric`），抓取结束后按时间戳就近（±1.2s）匹配到对应行，构建成"行号 → 译文"的映射缓存，逐帧查询是 O(1)；
4. 封面：优先用 SMTC 自带的；缺失时 QQ 按 albummid 拿图床、网易云按 picId 走 CDN 加密 id 算法拼出图片地址；
5. 歌词行按播放进度（本地插值平滑）驱动卡拉OK填色；封面取色用 HSV 分桶挑出两个鲜艳主色；
6. **逐字时间轴自适应**：逐字数据（网易云 YRC / 增强 LRC）只标到人声唱完，行的时间戳却排到下一句（一句话唱完挂几十秒尾奏很常见），两者对不齐时高亮会在行首几秒就全亮、之后整行静止到换行——看起来就是"进度几秒才更新一次"。所以拿到逐字轴后会**保持逐字相对节奏不变、把整段跨度等比铺满行时长**（尾部留 8% 余韵），高亮像进度条一样跟着播放位置走；本来就贴合的行不动。

## 已知限制

- 播放器需接入系统媒体栏（QQ音乐 NT / 网易云新版默认接入；部分老版本或迷你模式可能没有）
- 播放器独家版权不覆盖的歌在对应平台搜不到原唱（例如周杰伦在网易云无版权），此时会落到另一来源或 LRCLIB；翻唱歌词的逐行时间与原唱录音不一定一致
- 网易云 weapi 搜索依赖 `pycryptodome`；未安装时自动降级到老接口（匹配质量变差）
- 翻译歌词依赖音源是否提供（QQ `trans` / 网易云 `tlyric`），LRCLIB 兜底来源通常没有翻译，此时该行不显示译文
- 逐字（卡拉OK字级）时间轴支持网易云 YRC、酷狗 KRC 与增强 LRC 来源，QQ 等行级来源会借网易云同曲时间轴补逐字，拿不到时按行内均匀推进
- **QQ 音乐的 QRC 逐字歌词未接入**：QRC 需要 3DES 解密，实测多种密钥/模式组合都拿不到合法 zlib 流，怀疑与请求的版本参数有关，因此 QQ 仍走 LRC（逐行）；QQ 的独家逐字内容会借网易云补
- 制作名单识别是**启发式**：基于「角色词 + 冒号」，若遇到没收录的写法（新奇的英文署名等）可能漏过，可在 `_CREDIT_ROLE` 里补一个词；反向误伤的概率很低但非零
- 繁简转换内置的是**高频字表**（900+ 组），少见繁体字不在表内会原样保留；需要完整转换请自备 `t2s.tsv`
- Apple Music（TTML）/ Spotify / Musixmatch 等来源**未接入**：它们需要用户侧凭据（Media User Token / `sp_dc` Cookie / User Token），与本程序"零配置"的定位不符
- 全局快捷键需要独占组合键：若被其它程序（如 Intel 显卡驱动的 `Ctrl+Alt+方向键` 屏幕旋转）占用，程序会自动跳过并在启用时提示，可用托盘菜单关闭该功能；该项**默认关闭**
- 字体库自带 jsDelivr 主源 + ghfast.top / ghproxy.net 等国内镜像回退；若全部失败，面板按钮会变「重试」，点一次即可重新尝试
- 氛围屏保的「空闲自动进入」靠 `GetLastInputInfo` 判断键鼠空闲；播放视频时系统仍算「有输入」，不会误触发（除非真的没碰键鼠）
- 打包成 exe 后，`fonts/` 目录可能不可写，因此字体库一律下载到 `%APPDATA%\Desktop-sing\fonts`

### 安装器 v2 修正：自动关闭正在运行的实例（修复"无法打开要写入的文件"）

首版安装器在**桌面歌词正在运行**时安装/重装，`_internal\*.pyd` 等文件被进程
锁死，每个文件都弹「无法打开要写入的文件」——尤其是先解压了免安装版并从
同一目录启动、或安装完点了"立即运行"再重装的场景。

修正（`installer/installer.nsi`）：安装与卸载的 `.onInit` 里用
`tasklist + find` 管道检测 `Desktop-sing.exe` 进程，检测到就弹窗询问，
确认后 `taskkill /F /T` 关闭并等待 800ms 再继续。两个坑已实测踩平：

1. **NSIS 没有内置 `$COMSPEC` 常量**（用了会静默变成空命令、nsExec 报
   error），必须 `ReadEnvStr $R2 "COMSPEC"`；
2. 裸 `tasklist /FI` 无论是否命中退出码都是 0，只有接 `find` 后
   「0=有进程 / 1=无进程」的语义才可靠。

验证：静默安装（/S /D=测试目录）→ 文件完整（69 个 _internal 文件含
_ssl.pyd）→ 静默卸载 → 目录干净删除，全链路通过。

### 安装器 v3：纯 ASCII 默认目录 + 「文件占用」实测探测

用户复测仍报「无法打开要写入的文件」（说明占用来源不一定是
`Desktop-sing.exe` 这个进程名），并且要求安装目录不要中文。本版调整：

1. **默认安装目录改为 `D:/Desktop-sing`**（原 `D:/桌面歌词`）；无 D 盘时兜底
   `%LOCALAPPDATA%\Desktop-sing`。免安装包的解压顶层目录同样改为
   `Desktop-sing-v1.0.0`。ASCII 路径同时规避了权限 / 杀软 / 编码类偶发问题；
2. **不再只靠进程名判断**：装/卸载前先按进程名 `taskkill` 一次（若在运行会
   先弹窗确认），随后**直接对 `$INSTDIR\Desktop-sing.exe` 做可写探测**
   （`FileOpen ... a`）——任何原因造成的占用（进程改名、杀软扫描、权限）都能
   抓到，并弹出带处理步骤的「重试 / 取消」对话框，最多重试 60 次；宁可中止，
   也不写坏半套文件。

验证（静默模式实测）：

| 场景 | 结果 |
|---|---|
| 目标空闲 | 安装成功，69 个 `_internal` 文件齐全，exe 与源文件 sha256 一致 |
| 独占占用目标 exe | 安装器**中止**（exit=2），既有文件零覆盖、目录保持完整 |
| 占用解除 | 恢复正常安装 |
| 锁探测单测 | 空闲=WRITABLE / 独占=LOCKED / 释放=WRITABLE，三态均正确 |
| 静默卸载 | 目录干净删除 |

> 若再遇到占用提示，按对话框里的三步处理（托盘退出 → 任务管理器结束
> Desktop-sing.exe → 等杀软扫描结束）后点「重试」即可。

### 安装器 v4：D 盘不可写时自动兜底（用户实测根因）

用户的真实根因是**本机 D 盘没有写入权限**（不是进程占用）。v4 起把「目录
可写性」也纳入安装前检查：

`DirWritable`（对一个目录实测写临时文件再删）在三处使用：

1. `.onInit`：默认目录 `D:/Desktop-sing` 不可写 → 弹窗告知后自动改用
   `%LOCALAPPDATA%\Desktop-sing`；用户显式指定的目录不可写 → 明确报错并中止，
   不擅自改；兜底目录也不可写 → 报错中止（绝不半装）；
2. `.onVerifyInstDir`：在「安装目录」页选到不可写的位置时拦下，提示换个可写的；
3. 配合 v3 的 `EnsureWritable`（进程占用探测）一起，覆盖「占用」与「无权限」
   两类写失败。

实测（静默模式）：可写目录 → 69 个文件装齐；`Q:/nope` → 中止且零写入；
默认 D 盘不可写 → **自动装到 `%LOCALAPPDATA%\Desktop-sing` 并成功**，卸载后
目录干净移除。免安装包顶层目录与安装目录均为纯 ASCII。
